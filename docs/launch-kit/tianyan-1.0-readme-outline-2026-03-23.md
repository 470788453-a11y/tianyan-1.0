## 项目一句话介绍

**天衍 1.0** 是一套面向真实任务推进的开源 AI 运行框架，重点解决“任务怎么拆、怎么执行、怎么记录、怎么收口”这四件事。

可替换短版：

> 天衍 1.0 是一个强调可执行、可追踪、可收口的 AI 任务运行框架。

如果想更偏 GitHub 风格，也可以用这一版：

> Tianyan 1.0 is an open-source AI runtime framework focused on task execution, traceability, and delivery closure.

---

## 项目简介

很多 AI 项目擅长“生成一个回答”，但不一定擅长把一个任务稳定地推进到结束。

天衍 1.0 想做的不是再包一层概念，而是把下面几件基础能力组织清楚：

- 任务目标怎么定义
- 执行过程怎么拆阶段
- 关键动作怎么留痕
- 人和系统怎么协同确认
- 一个结果怎么被判断为“真的完成了”

如果你正在找的是一个更偏“运行与交付”的开源项目，而不是单纯的聊天壳或演示工程，天衍 1.0 可以作为一个起点。

## 核心特性

> 这一节建议只保留仓库里真实存在的能力。下面是安全、克制的写法。

### 1. 任务导向，而不是只做对话
- 关注任务推进，而不只是单轮回答
- 更适合需要分步骤执行、阶段汇报、结果收口的场景

### 2. 过程可追踪
- 鼓励把关键状态、关键决策、关键结果记录下来
- 便于后续复盘、移交、回看和继续推进

### 3. 结构化组织
- 把运行逻辑、文档、配置、样例尽量分层放置
- 降低项目后期越做越乱的概率

### 4. 人在回路中
- 适合需要人工确认、人工兜底、人工裁决的任务流
- 不默认把“能生成”当成“能交付”

### 5. 便于后续扩展
- 1.0 先把基础骨架立住
- 后续可以继续接入更多执行链路、验证链路和协作方式

如果你需要更短的 GitHub 首页版，可以直接写成：

- 面向真实任务推进
- 强调过程留痕与结果收口
- 支持从最小骨架逐步扩展
- 适合做个人 / 小团队 AI 运行底座实验

## 架构 / 目录建议

> 如果你还没完全定目录，这里可以直接拿去改。

```text
.
├─ docs/                # 文档、设计说明、路线图、发布材料
├─ src/                 # 核心源码
├─ scripts/             # 启动、校验、构建、辅助脚本
├─ runtime/             # 运行时状态、样例配置、运行面板
├─ config/              # 配置模板与 schema
├─ examples/            # 最小样例 / 演示用例
├─ receipts/            # 关键执行结果 / 回执 / 留痕
├─ tests/               # 测试
├─ .env.example         # 环境变量示例
├─ README.md            # 仓库首页说明
└─ LICENSE              # 开源协议
```

如果想在 README 里对目录逐条解释，可以直接写：

- `src/`：核心运行逻辑
- `docs/`：设计、说明、路线图和发布文案
- `scripts/`：辅助脚本与校验工具
- `runtime/`：运行时样例、状态或最小配置
- `receipts/`：关键动作留痕
- `examples/`：最小可复现示例

## 当前版本边界

建议在 README 里主动写清楚 1.0 的边界，避免误解：

- 当前版本优先解决“骨架是否清楚”
- 当前版本不承诺覆盖所有场景
- 当前版本不默认等于完整商业化产品
- 当前版本更适合作为开源起点，而不是最终形态

可直接复制的一句话：

> 天衍 1.0 更像一个开源起点版本：先把最小骨架、基本流程和核心思路公开出来，再逐步补齐工程化细节。
